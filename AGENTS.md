# open-receipt

An iOS app that reads receipts and splits bills.

## Principles

- Apple platforms only: Swift, SwiftUI, and the iOS SDK.
- Scanned or imported receipt images go straight to `PrivateCloudComputeLanguageModel` (PCC). The model reads the receipt; our code decodes and validates its response.
- Never add heuristics tailored to specific fixtures. Recognition must work from the images alone.

## Layout

- `Fixtures/Receipts/<name>/` holds parser fixtures: `fixtures/<n>.png` plus `expected.json`. See [Fixtures/README.md](Fixtures/README.md).
- `Assets/Icons/`, `Assets/ScreenshotData/`, and `Assets/Previews/` are generated by `make icons` and `make previews`. Don't edit them by hand. Only `Assets/Previews/light/` and `Assets/Previews/artwork/` are checked in: the README shows the light screenshots, and the artwork is uploaded to App Store Connect.

## How the app behaves

- Debug and Release behave the same. `BuildChannel` decides behavior at runtime (development, TestFlight, or App Store), so don't add `#if DEBUG` branches for app behavior. Release is only signed and optimized.
- The simulator has no PCC, so it can only read sample receipts.
- Reading is always an explicit action. Opening an unread receipt never calls PCC.
- Users get a few free reads before buying Unlimited Reading. A retry or a resumed read counts as the same read, and a read that fails before any items appear gives its free read back. Keep this true when changing the read flow.
- Debug builds can't reach StoreKit, so they use a stand-in purchase. Launch with `-DebugUnlimitedReading YES` to start unlocked.
- The receipt background is a Metal shader, so builds need Xcode's Metal Toolchain component.

## Commands

Use `make` for everything, run from the repository root. Run `make help` to see the targets.

- Never call `swift`, `xcodebuild`, `xcrun`, or the ReceiptLab binary directly.
- Run each `make` call on its own. Don't pipe, redirect, env-prefix, or chain it with `cd`, `&&`, or `;`, because that triggers sandbox escalation. Use the built-in flags instead.
- `make test fast=1` runs only the SPM tests.
- Builds use Debug by default. `release=1` signs a Release build, which you need to test live PCC and StoreKit on a device.

## Receipt harness

`make receipts` runs the parser against the fixtures through live PCC and compares the results to each `expected.json`. It's the main loop for parser work. It exits non-zero if any fixture fails.

Example: `make receipts of=whole-foods-1 format=summary`

- `of=` runs one fixture (`name`), one sample (`name/n`), or a path.
- `cached=1` replays saved responses instead of calling PCC. A response is only reused when the prompt, instructions, image, and contract version all match exactly.
- When you change generation options, bump `ReceiptModelContract.version`.
- `filter=`, `head=`, and `tail=` trim the output, since you can't pipe it.
- `reasoning=` and `max_pixels=` try settings other than the shipped `ReceiptParserConfiguration.standard`. Compare accuracy and speed before changing the standard.
- Other flags are listed above the `receipts` target in the `Makefile`.

## Screenshots

`make previews` captures and renders the App Store screenshots, plus the header and search result artwork in `Assets/Previews/artwork/`. The header's slips are drawn by the app itself, so they match what people are sent. For design or copy changes, use `cached=1` to re-render without capturing again.

## Conventions

- No emojis in code, comments, logs, or commit messages unless asked.
- Comment only public APIs or genuinely non-obvious logic.
- Prefer many small, focused tests over large table-driven ones.
- In user-facing text, "scan" means only the document camera (and "Scan. Split. Settle."). "Read" means the model reading a scanned or imported receipt, and that's what free reads and Unlimited Reading count.
- Tests must never call PCC, because it uses quota. In app tests, inject a `ReceiptParsingClient` (never `.standard` or `.live`). In harness tests, use a fake `ReceiptModelClient.Respond`. Only `make receipts` makes live calls.
